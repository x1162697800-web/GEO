## 1. 为什么排最后

**先修漏斗，再灌水。**

## 2. 战略依据：这招被验证有效

Nile 的做法值得抄：**完整方法论 + CC BY 4.0 开源数据 + GitHub 仓库 +
声明可复现可争议**。

他们那份《Agentic Commerce Readiness Index 2026 — Edition 1: DTC Beauty》
做了：40 个品牌、9 条判据、公开 `methodology.md` / `scores.csv` /
`scores.details.jsonl` / 逐品牌审计 JSON+HTML、一个 GitHub Pages 看板。
产出了一个可传播的概念（**The Content Cliff**）和一堆可引用的数字。

**而 geolook 的处境比他们好三点：**

1. **引擎更强** — 四层依赖模型 + 段落级可引判据，比他们的 9 条判据深一层
2. **手里有他们的 bug** — 已完成 50 品牌交叉验证（见 `reference/nile-teardown.md`）
3. **他们停在第一期** — Edition 1 只做了美妆，Edition 2 还「待定」

## 3. 现成的传播钩子

本轮交叉验证的结果本身就是一篇研究：

> 我们用同一批样本复现了这份榜单。39 个七项全测出的品牌里，
> C3（sitemap 新鲜度）判据一致率只有 **51%**——19 个被判失败的品牌实测通过，
> **0 个反向**，且这 19 个的 `lastmod` 全部带非 UTC 时区偏移。
> 配合他们自己数据里那条 `can't compare offset-naive and offset-aware datetimes`
> 异常，这是一个确定性 bug，让这条判据的通过率被系统性低估了约一半。

加上更值得说的方法论问题（R3）：

> 更影响结论的是：他们把「测不到」记成 0 分。5 个首页返回 200 的品牌
> 被记了真实分数（只是 PDP 取样失败），1 个（Adwoa Beauty）因为 scorer 崩溃
> 被记 0 并写进「无法抓取」排除组——而它实测首页 200、7 个 AI 爬虫全放行。
> 「中位数 4/9」「零品牌达到 Agent-Ready」这些头条结论建立在这个混淆上。

以及 geolook 独有层能给出的、他们的判据看不到的东西：

```
40 个品牌 120 个 PDP
六维均分        53.0 / 100
平均词数        683 词        （1000 词是高影响力门槛）
可引段落        105 / 478 = 22.0%
零可引段落品牌  10 / 40
评级分布        A:2  B:30  C:53  D:35   → 73% 是 C/D
```

**这是段落级分辨率的 Content Cliff。** 他们的 C9 说「描述不够好」（通过率 12.5%），
geolook 能说「478 个小节里只有 105 个含数字/定义/步骤，10 个品牌整站零可引段落」——
同一个结论，但能直接指到该改哪一段。

## 4. 发布纪律（不许破）

### R5 · 速率纪律

本轮第一次跑批的教训必须写进方法论：5 并发 × 每品牌 14 请求，
50 个品牌里 **24 个撞 HTTP 429**，数据全废。同一个站单独跑得 6 分、
混在批里跑得 0 分——**自己的并发污染了自己的结论**。

重跑用串行 + 退避 + 品牌间隔，耗时 92 分钟，零污染。
**发布的方法论里要写明速率参数**，这既是可复现性要求，也是对被测站点的基本尊重。

### R3 · 未测 ≠ 不通过

这是我们批评对手的核心点，自己更不能犯。发布的数据里：

- 任何取不到证据的判据记「未测」，绝不记 0
- 聚合统计只对「全部判据都测出」的样本计算，样本数要明示
- 未测样本单独列出并说明原因（首页不可达 / SSL 错误 / PDP 取样失败 / 限流）

### R9 · 归因与断言的诚实口径

- 与对手的差异不能全归因为「对手有 bug」。本轮实测里：
  - **C3 的 +19 是确证的 bug**（方向 100% 单向 + 全部命中时区条件 + 有异常原文）
  - **C7 的 −4 是我们更严**（4 个他们过我们不过，0 个反向），要如实写
  - **C5 的 +9 无法归因**——他们那篇文章明确写了「启用 review schema 是最快的 +1」，
    4 个月里品牌方真去开了 widget 开关是完全合理的解释。
    **这部分差异可能恰恰是他们那份报告起了作用，要写进去**
- **时间差必须显著标注**：他们评分于 2026-04-18，我们复现于 2026-08-22，
  间隔 4 个月。除 C3 外的所有差异都无法干净地区分「口径差异」与「站点变化」
- 不做「geolook 比 Nile 准」这种整体性断言——只报可支撑的具体条目

### 数据质量的自查项

- `llms.txt 41/50` 这个数字**不可信，不能发**。`fetch_text` 只看 200，
  而很多 Shopify 站对不存在的路径返回 200 + 404 页面模板，
  这个 82% 采纳率大概率被软 404 灌水。要发必须先加内容特征校验
  （这本身是 geolook 该修的一个真实缺陷，可以顺手带进 P3）

## 5. 可选的选题方向

Nile 只做了美妆。可选：

| 方向 | 优势 |
|---|---|
| **复现 + 修正他们的美妆榜** | 钩子最强（直接对话已有讨论），样本已跑完 |
| 中国市场品类榜 | 完全空白，且 geolook 的 CN 引擎矩阵和 CN 阵地数据是独家 |
| 非电商品类（B2B / SaaS / 专业服务） | **对手结构性打不到的地方**，且是 GEO 主战场 |

第三个方向战略价值最高——Nile 在 `/compare` 打 GEO 工具的论点
（「内容优化让你被提及，不让你被购买」）只在电商 SKU 场景成立。
B2B / SaaS / 服务业没有 SKU 可上架，他们的模型完全不适用。
在那里做一份榜单，是在他们进不来的地方立桩。
