# 贯穿纪律（红线）

执行任何阶段前先读这一份。这些不是建议，是**破了就要回滚**的约束。
每条都标了来源——要么是 geolook 已有的方法论纪律，要么是本轮实测踩出来的。

---

## R1 · 实证锚定：给用户的每条建议都要能追到数据

**来源**：`references/method.md` 开篇——「凡是给用户的建议，都要能追到这里的某一条」。

geolook 最硬的差异化不是功能多，是**六维评分每条阈值都对应公开实证数字**
（1,943 词 vs 170 词、数字 +61.6%、定义 +57.3%、对题性 r=0.432、官网仅占 1.37% 引用）。
竞品的判据基本是拍脑袋——包括 Nile 那 9 条，它们没有任何公开的效果验证。

**约束**：新增任何评分维度或阈值，必须满足其一：

1. 找到公开实证锚定，写进 `method.md` 并注明来源
2. 明确标成**另一类判断**（如「渠道准入要求」而非「影响力预测」），
   在 UI 和报告里与六维分数分开呈现
3. 不做

**直接影响**：P3 电商维度。变体级活库存、运费资格、`gtin/mpn/sku` 这三条
没有实证支撑——它们是 Nile 的判据，而 Nile 的判据未经验证。

**D3 已按上述第 2 条定案**：归入四层模型的「理解层门票判据」，
依据是协议 schema 而非效果实证，且不进六维总分。
四层模型本来就区分门票与杠杆（访问层、定向层全是资格判据），所以这不是破例。

## R2 · 指标只能有一份实现

**来源**：README「Metrics: 完全可复现；UI 里有『这些数字从哪来』面板；
未测量的显示『未测量』，绝不编造」。

**约束**：提及率、首位率/Top3、描述准确率、引用质量、citation share
这些指标**只能在平台里计算**。

插件（含未来的独立模式）只允许产出：

- 原始样本（答案全文 + 引用链接 + 采样环境 `session_mode`）
- 一个**平凡可导**的指示：提到 / 没提到

一旦插件里出现第二套指标实现，两边必然漂移，而「指标完全可复现」这个定位
是靠单一实现撑住的。

**直接影响**：P1b 插件独立化。**D2 已定为方案 A**：独立模式只到
「提到/没提到」，且只能朝「未提及」方向呈现结论——`personal` 采样模式偏向
「更容易提到自己」，所以「没提到」是保守估计（可用），「提及率还不错」（禁用）。
这条要在代码层面约束，不能靠文案自觉。

## R3 · 「测不到」不等于「不通过」

**来源**：本轮实测。这是 Nile 那份榜单最核心的缺陷，也是我第一轮跑批犯的同样错误。

Nile 的 `scores.csv` 里：

- Adwoa Beauty 因为 scorer 抛 `can't compare offset-naive and offset-aware datetimes`
  被记 0 分并写进「无法抓取」排除组——**实测首页 200，7 个 AI 爬虫全放行**
- Drunk Elephant / Biossance / Item Beauty / Briogeo 被记了 1–3 分的**真实分数**，
  而实测首页全部 200，只是 PDP 取样失败

他们把抓取失败和判据不通过混成同一个 0，中位数 4/9、「零品牌达到 Agent-Ready」
这些头条结论都建立在这个混淆上。

**约束**：任何判据取不到证据时必须记 `None`/「未测」，**绝不记 0**。
聚合统计只对「两边都测出」的样本计算，未测样本单独列出并说明原因。

## R4 · 区分「按身份拒绝」与「速率/容量」

**来源**：本轮修复的 `probe_ai_ua` bug。

| 状态码 | 语义 | 处理 |
|---|---|---|
| 401 / 403 / 406 / 451 | 按身份拒绝 → **真差异封锁** | 进 `ai_ua_blocked` |
| 429 / 503 | 速率/容量，与 UA 无关 | 退避重试；仍失败进 `ai_ua_rate_limited`（未测） |

把 429 读成「WAF 封了 AI 爬虫」是 P0 级误报，会诱导用户去动 WAF——
按 `method.md` 第 7 节那是最高风险改造。而探测本身对同一页连发数个请求，
**极易自己把自己打成 429**。

**约束**：任何主动探测都必须（a）退避重试，（b）用默认 UA 打基线对照，
（c）基线也被限速时整轮判为不可结论。

## R5 · 抓取别人的站要有速率纪律

**来源**：本轮第一次跑批的失败。5 并发 × 每品牌 14 请求，50 个品牌里
**24 个撞 HTTP 429**，数据全废，重跑耗时 92 分钟。

同一个站（Rare Beauty）单独跑得 6 分、混在批里跑得 0 分——自己的并发污染了自己的结论。

**约束**：批量抓取外部站点时串行或极低并发，品牌间留间隔，撞限流退避重试。
宁可慢，不要拿污染的数据下结论。

## R6 · 风险等级与优先级独立

**来源**：`references/method.md` 第 7 节。

优先级说「多重要」，风险说「动手时多小心」，**两者独立**。

| 等级 | 含义 | 纪律 |
|---|---|---|
| 低风险 | 纯新增模块/资产，不改已有逻辑 | 先做这批建立信任，随时可撤 |
| 需观察 | 改已有逻辑或已有页面 | 不改公开接口语义；改完立刻跑全量测试 |
| 高风险 | 动锁、进程管理、发布流程、渲染架构 | 改前备份、单独排期、小批量、留回滚；改完两平台都实测 |

**直接影响**：P0 是最高优先级，同时是**高风险技术改造**——它动文件锁和进程管理。
两者不矛盾：优先做，但要最小心地做。

## R7 · 不破坏「恰好三个第三方包」

**来源**：README 把 `requests` / `beautifulsoup4` / `lxml` 作为卖点写在依赖徽章和
部署章节里；「无 DB、无账号、数据是纯文件」是同一套定位的一部分。

**约束**：新增第三方依赖必须过一道显式决策，写进 `DECISIONS.md`。
标准库能解决的优先手写。

**直接影响**：P2b MCP server。**D1 已定为手写** stdio JSON-RPC，不引入 SDK。
定案依据：dashboard 用标准库 `http.server` 而非 Flask 是同一条路——
「少依赖」这条你已经付过一次手写的代价，且它是可维护的。

## R8 · 平台声明必须与实现一致

**来源**：Nile 的反面教材。它们官网写着

> "Nile needs to read catalog, price, and inventory ... **nothing more**.
> Storefront, checkout, and OMS code are untouched."
> "server-side attribution, so measurement does not depend on a browser pixel"

而 Shopify 权限清单实际是 Edit products / Edit orders / **Edit Online Store（主题、
结算页）** / Edit store analytics（Web pixels），归因就是浏览器 pixel。

**约束**：README / SKILL.md / UI 里的每条能力与安全声明，都要与代码实际行为一致。
平台差异要写明——例如 Windows 上 `.env` 的 `chmod 0o600` 是空操作，
「密钥文件不给同机其他用户读」这条在 Windows 上**不成立**，必须在文档里讲清楚
（见 `P0-windows.md`）。

## R9 · 发布与归因的诚实口径

**来源**：`references/method.md` 第 4、8 节。

- 归因默认写「观察相关」，不写因果
- App 内打开常不带 referrer，AI 流量是**下界**，报告写「可归因的 AI 会话 ≥ N」
- 永远不承诺「某平台一定会引用某页」，只承诺提升可发现性/可验证性/可抽取性
- 单轮波动标为观察，只有连续两轮同向才算趋势

**直接影响**：P4 开源研究的所有对外表述。
