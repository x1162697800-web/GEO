# P1 · 插件独立化 + 上架

**优先级**：高（P1a 应与 P0 并行启动）
**风险等级**：P1a 低 / P1b 需观察
**依赖**：无。决策 **D2 已定（方案 A + 单向使用纪律）**
**前置阅读**：`RULES.md` R2、R9

拆成两半，**长杆是上架不是开发**：

- **P1a 商店材料**：无技术依赖，审核周期以周计 → **现在就该启动**
- **P1b 独立化开发**：可晚于 P1a，等 D2 定了再动

---

## 1. 问题定义

`extension/manifest.json`：

```json
"permissions": ["sidePanel", "storage", "tabs"],
"host_permissions": ["http://127.0.0.1:8765/*"]
```

插件只能回传本机 8765，**平台不跑它就没用**。加上现在是 v0.1.0 走
load unpacked（`sandbox.sh` 加载未打包扩展），完整安装漏斗是：

```
装 Python → clone 仓库 → pip install → 起 dashboard → 开发者模式 load unpacked
```

非技术用户在第一步就流失。**结果是：插件是配件，不是入口。**

而它本该是最好的入口——19 个引擎的 content script 已经写好
（ChatGPT / Claude / Perplexity / Gemini / Google / 豆包 / 智谱 / Kimi / 元宝 /
文心 / 百度 / n.cn / 秘塔），队列、答案提取、引用抽取全都有了。
**能力已经在了，只是被锁在平台后面。**

## 2. P1a · 商店上架材料

### 为什么先做这个

Chrome Web Store 审核周期以周计，且**大概率要来回一两轮**——这个插件会读取
第三方 AI 站点页面内容，属于审核员会仔细看的类型。这是整个规划里唯一一项
「提前启动能省真实时间」的工作。

### 清单

- [ ] **图标**：128 / 48 / 16 三档（manifest 现在完全没有 `icons` 字段）
- [ ] **商店截图**：1280×800 或 640×400，至少 1 张，建议 3–5 张
- [ ] **隐私政策页**：必须有可公开访问的 URL。挂在 `geolook.cc/privacy` 下即可
- [ ] **权限说明**：逐条解释为什么需要 `sidePanel` / `storage` / `tabs`
      以及 19 个 host match
- [ ] **数据用途声明**：Chrome 商店要求申报是否收集用户数据。
      geolook 的答案很有利——**样本只存本机/本浏览器，不上传任何服务器**，
      这点要写清楚，它同时是卖点
- [ ] **商店描述**：中英双语
- [ ] 决定发布形态：公开列出 / 不公开列出（unlisted）/ 私有
      → 建议**先 unlisted**，拿到稳定安装链接但不进搜索，避免在 P1b 完成前
      涌入用户看到半成品

### 审核风险点（提前准备说明）

| 风险 | 说明准备 |
|---|---|
| content script 注入 19 个第三方站点 | 说明用途是「读取用户自己发起的对话结果」，不修改页面、不代替用户操作 |
| 自动跑队列模式 | 现有 README 已诚实记录 ToS 风险。建议**商店版默认关闭并移除该开关**，只留手动模式（见第 4 节） |
| `tabs` 权限 | 说明只用于识别当前所在引擎，不读取无关标签页 |

## 3. P1b · 独立化开发

### 目标

不装平台也能得到一个真实结论：**「10 个买家意图问题里，8 个没提到你」**，
然后才是「装平台来修它」。

### 边界（D2 已定：方案 A）

按 `RULES.md` R2，指标只能有一份实现。独立模式**只允许**产出：

- 原始样本：答案全文 + 引用链接 + 采样环境 `session_mode`
- 一个平凡可导的指示：提到 / 没提到

**不允许**：提及率、首位率、Top3、引用份额、描述准确率——这些只能在平台算。

理由：入口产品的任务是**制造动机**，不是给结论。「8/10 没提到你」这个事实
本身就足够刺痛，算出「提及率 20%」不更刺痛，却要付双实现漂移的代价。

### 需要新增的东西

| 项 | 说明 |
|---|---|
| 内置默认问题集 | 无平台时的问题来源。需定：一份通用买家意图模板？还是按行业几套？（D2 配套问题） |
| 品牌名/别名输入 | 独立模式下没有平台的品牌事实库，用户得自己填。**别名缺失会低估提及率**——这点要在 UI 上提示 |
| 本地存储 | 已有 `storage` 权限，样本存 `chrome.storage.local` |
| 导出/交接 | 导出成平台 `sample-import` 能吃的格式，实现「先用插件，后装平台接管」 |
| 平台探测 | 检测 127.0.0.1:8765 是否在跑，在则走原有回传流程，不在则走独立模式 |

### 采样环境问题与它的化解（D2 的核心）

按 `references/method.md` 第 4 节：`sandbox` / `incognito` / `clean_profile`
是 A 级证据，`personal`（个人日常账号）**自动降级 D 级待复核**——
它测的是「AI 对你的画像」，不是「陌生人看到什么」。

**独立模式的现实是：绝大多数用户会在日常登录态下用它。** 也就是说产出的样本
按纪律应大量是 D 级——入口产品的核心结论建立在弱证据上。

**方向性化解了这个问题。** `personal` 模式的偏差是朝着
**「更容易提到你自己」**的方向的：用户搜过自己品牌，AI 有其上下文与记忆，
所以它比陌生人更可能提到该品牌。

由此得出**单向使用纪律**：

| 结论方向 | 是否可用 | 理由 |
|---|---|---|
| 「N/M 没提到你」 | ✅ 可用 | personal 模式下是**保守估计**，真实只会更差 |
| 「提及率还不错」 | ❌ **禁止** | personal 模式下完全不能作为好消息 |

这样既保住入口产品的钩子，又不违反证据分级。**UI 必须在代码层面约束
只呈现「未提及」方向**，不能靠文案自觉。

配套仍要做：

- 结果上标注采样环境，引导用户开无痕重跑
  （Windows 用户没有 `sandbox.sh`，见 `P0-windows.md` 第 3 节）
- 导入平台时保持 D 级标记，**不因为「是插件采的」就升级**
- 品牌别名让用户填，并提示「别名缺失会低估提及」

**绝不能为了让入口产品的结论好看而放松这条纪律**（R9）。

## 4. 一个建议：商店版移除自动跑队列

现有 `extension/README.md` 诚实记录了自动模式的 ToS 风险，并加了硬护栏
（人须在场、限速、有上限、遇验证码即停）。开源自用版保留这个能力是合理的。

但**商店版建议移除**，两个理由：

1. 审核风险最高的就是这个功能，可能导致整个上架被拒
2. 上架后如果因此被下架，会连带影响项目声誉

做法：商店版和仓库版用同一份代码，靠构建期开关剔除自动模式，
仓库 README 说明「自动模式仅在自行加载未打包版本时可用」。

## 5. 验收标准

### P1a

- [ ] 插件在 Chrome Web Store 有稳定安装链接（unlisted 亦可）
- [ ] 隐私政策 URL 可公开访问，内容与实际行为一致（R8）
- [ ] 数据用途申报准确：不上传任何服务器

### P1b

- [ ] 全新浏览器 + 未安装平台，能装上插件、跑完一轮默认问题集、看到「N/M 没提到你」
- [ ] 导出文件能被 `python scripts/geo.py sample-import` 正常吃进
- [ ] 平台在跑时，行为与现在完全一致（不回归）
- [ ] 独立模式**没有**计算任何比率型指标（代码审查确认，R2）
- [ ] UI **在代码层面**只能呈现「未提及」方向，无法展示正向提及率（D2 单向纪律）
- [ ] `session_mode` 标记正确，`personal` 场景在 UI 上有明确警示
- [ ] `extension/test/e2e.js` 覆盖独立模式路径

## 6. 不做什么

- **不在插件里做站点体检**。六维评分要抓多页、算结构统计，属于平台职责。
  插件碰这个就会变成第二个平台。
- **不做云端同步**。会砸掉「数据全在自己机器上」的定位。
- **不为独立模式单独建后端**。同上。
